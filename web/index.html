Stop paying for sandboxes. Run coding agents on your own VM.

forgerun is an open-source (Apache-2.0), fully self-hosted cloud coding-agent platform written in Go that turns machines you already own into managed sandboxes. Queue as many end-to-end tasks as you want across Claude Code (including unattended bypassPermissions / --dangerously-skip-permissions), Cursor CLI, OpenCode, pi, and Prime Agent in one place — or hand work off mid-task from your local agent via forgerun mcp. Every conversation thread runs in its own isolated sandbox: a hardware-virtualized microVM via microsandbox (libkrun) on Apple Silicon Macs (HVF) and Linux with KVM, or a gVisor user-space kernel sandbox (0.34s cold boot) on any standard Linux VPS without nested virtualization. Automatic rolling disk snapshots start tasks in 2.8 seconds, API keys never enter the sandbox, and nothing is pushed to GitHub until you review the diff and push as yourself.

How it works

  1. 01. Queue tasks or hand off mid-session

    Pick a GitHub repository (any branch), an agent (cursor, claude-code, opencode, pi, or prime), and a model, then queue as many tasks as you want — or ask for a read-only plan first and approve it before any code is modified. Coding locally? Use forgerun mcp (forgerun_handoff) to hand off your in-progress folder and session summary straight to a cloud sandbox thread.

  2. 02. It works end to end in a managed microVM

    Workers claim queued turns automatically and boot a dedicated VM (images include git, Node, and Python) where the agent clones, installs packages, builds, and runs tests. Automatic rolling disk snapshots reduce task startup time from 26.8 seconds to 2.8 seconds (measured on expressjs/express with 304 npm packages pre-installed) and self-clean within your disk budget. The VM stays alive between follow-up messages, and you can switch agents or models mid-thread.

  3. 03. Review the diff, then push as you

    Inspect the live execution log and unified git diff for each turn in the web UI. Nothing touches your repository automatically: only when you press push does the host publish a single squashed commit to a forgerun/… branch and optionally open a GitHub pull request under your own identity.

Why it's safe to point at your code

  • One managed sandbox per thread

    Each thread executes inside its own libkrun microVM (or a gVisor runsc container with a dedicated user-space kernel booting in 0.34s on KVM-less Linux hosts). Untrusted code, postinstall scripts, and unattended agent commands stay isolated from your host kernel. Claude Code runs with IS_SANDBOX=1 and ENABLE_CLAUDEAI_MCP_SERVERS=false so personal connectors stay off.

  • Brokered secrets: keys never enter the sandbox

    Inside the sandbox, credential environment variables contain only inert placeholders ($MSB_… or FORGERUN_PH_…). A host-side TLS proxy swaps in the real API key exclusively for requests destined to the agent's official API endpoint, blocking exfiltration to any other domain.

  • Nothing reaches GitHub until you push

    Agents have no GitHub push credentials inside the sandbox. Private repositories are fetched on the host; changes leave the sandbox only as a git diff and are pushed by the host as you only when you click push.

Supported Agents & Subscriptions

  • cursor — Cursor CLI with full model catalog, thinking modes, and effort controls.
  • claude-code — Anthropic Claude Code (Sonnet, Opus, Fable) using your existing Claude Pro or Max subscription via claude setup-token.
  • opencode — OpenCode CLI, including zero-configuration free models that require no API key.
  • pi — Multi-provider coding agent supporting OpenRouter, OpenAI, and Anthropic keys.
  • prime — Prime Agent: those providers plus Gemini, xAI, and Prime Inference.

Drive forgerun from Claude Code, Cursor, or any MCP client with forgerun mcp: hand off a local folder mid-task (secret files filtered out), queue threads, follow them, review diffs, and push.

Run it yourself

Deploy everything in one binary (forgerun serve) on an Apple Silicon Mac or Linux server, or split the lightweight web orchestrator (forgerun server) on a $5 VPS while connecting outbound workers (forgerun worker) from your own hardware over HTTPS with zero open inbound ports. Run forgerun doctor anytime to verify KVM, gVisor, microsandbox, Postgres, and token readiness.

Frequently asked questions

How is forgerun different from Cursor Cloud Agents, Claude Code on the web, Codex Cloud, Devin, or OpenHands?

Cursor Cloud Agents, Claude Code on the web, OpenAI Codex Cloud, GitHub Copilot coding agent, and Devin run in vendor-managed clouds and lock you to one vendor's agent and billing. OpenHands is open source, but runs its own single built-in agent in Docker containers. forgerun (github.com/depak7/forgerun) is 100% open source (Apache-2.0) and turns machines you already own into managed libkrun microVM or gVisor sandboxes where you can queue tasks across Claude Code, Cursor CLI, OpenCode, pi, and Prime Agent in one place, hand off work mid-task via forgerun mcp, start in 2.8s from rolling snapshots, keep API keys out of the sandbox, and push PRs as you only when you want to.

How is forgerun different from cloud sandbox providers like E2B, Daytona, Modal, or Fly.io Sprites?

Those sell raw cloud sandbox VMs by the second (or provide a low-level SDK where you still have to build the agent runner yourself). forgerun uses your own Mac or Linux machines as the sandbox host (built on microsandbox and gVisor) and ships the complete end-to-end coding-agent platform out of the box: Postgres task queue, five agent adapters, automatic rolling repo snapshots, unified diff review, host-side branch and PR publishing, and forgerun mcp.

Can I queue multiple coding-agent tasks at once across different repos and agents?

Yes. Tasks sit in a Postgres queue, so you can queue as many as you want across repos, branches, and all five agents — even while workers are offline. Connected workers claim queued turns automatically as slots free up, each in its own isolated sandbox, and nothing is pushed to GitHub until you review the diff and click push.

Can I hand off an in-progress local session mid-task to a cloud coding agent?

Yes. Connect forgerun mcp to Claude Code, Cursor, or Codex and ask it to hand the rest off (forgerun_handoff). It uploads your local repo or folder (uncommitted changes included, while stripping .env and secret key files) along with a summary of what's done and what's left, and queues a cloud sandbox thread to finish the job.

How do I run Claude Code (--dangerously-skip-permissions) or Cursor CLI safely in a microVM?

Use forgerun: each conversation thread gets its own microsandbox microVM (or a gVisor sandbox on VMs without KVM). Claude Code runs with IS_SANDBOX=1, --permission-mode bypassPermissions (or plan), and ENABLE_CLAUDEAI_MCP_SERVERS=false so personal connectors stay off. The agent installs, builds, and tests inside that sandbox; keys never enter it; nothing reaches GitHub until you review the unified diff and press push. Live demo: forgerun.depak.dev.

Can I use my existing Claude Pro or Max subscription?

Yes. Run claude setup-token, set CLAUDE_CODE_OAUTH_TOKEN on the worker or server. Turns run against your subscription limits; the token stays on the host behind the secret proxy.

Does my Linux VPS need KVM or nested virtualization?

No. With KVM or Apple Silicon, forgerun boots a libkrun microVM. Without KVM, the installer sets up Docker + gVisor (runsc) so each thread still gets an isolated user-space kernel (0.34s cold boot).
